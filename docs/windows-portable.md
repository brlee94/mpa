# EML → PST 변환기

Windows와 **클래식 Outlook이 이미 설치된 PC**에서 사용하는 한국어 휴대용 변환기입니다. `Outlook.File.eml.15`는 일반적으로 Windows가 `.eml`에 붙이는 형식 이름입니다. 이 프로그램은 `.eml`과 실제 이름이 `.eml.15`로 끝나는 파일을 처리합니다.

## 사용 방법

1. 배포 ZIP을 PC의 로컬 폴더에 압축 해제합니다.
2. 클래식 Outlook을 한 번 열어 기본 프로필로 정상 실행되는지 확인합니다. Outlook을 관리자 권한으로 실행하지 마세요.
3. `EmlToPst.exe`를 실행합니다. 설치 프로그램, Python, .NET 별도 설치나 관리자 권한은 필요하지 않습니다.
4. **폴더 선택** 또는 **파일 선택**으로 EML을 고릅니다. 하위 폴더를 포함하면 PST의 `가져온 메일` 아래에 폴더 구조를 유지합니다.
5. **저장 위치**에서 기존 파일과 겹치지 않는 새 `.pst` 경로를 지정하고 **PST 변환 시작**을 누릅니다.
6. 완료 후 클래식 Outlook의 **파일 → 열기 및 내보내기 → Outlook 데이터 파일 열기**에서 PST를 엽니다.

원본 EML과 기존 PST는 수정하지 않습니다. 프로그램에서 메일을 보내거나 외부 변환 서버를 호출하지 않습니다. 기본 설정은 원본 EML을 각 항목에 추가로 첨부하므로, 변환 후에도 원본 전체를 꺼낼 수 있습니다. 이 옵션을 끄면 PST 용량을 줄일 수 있습니다.

## 조건과 동작

- 배포 파일은 **Windows 10/11 x64용**입니다. 클래식 Outlook과 정상적인 기본 프로필이 필요합니다. 새 Outlook만 설치된 PC에서는 동작하지 않습니다.
- .NET 10 LTS 런타임을 실행 파일에 포함합니다. 실행할 때 Windows 사용자 임시 폴더에 필요한 런타임 파일이 풀릴 수 있습니다. 별도 설치나 시스템 등록은 하지 않습니다.
- 제목, 텍스트/HTML 본문, 보낸 사람, To/Cc/Bcc, Reply-To, 메시지 ID, 메일 헤더, 보낸 날짜, 첨부파일을 가져옵니다. 수신 날짜는 첫 번째 유효한 `Received` 날짜를 사용하고, 없으면 `Date`를 사용합니다.
- 수신자 표시 이름은 원본 헤더에 보존되고, Outlook 수신자 목록에는 SMTP 주소를 넣습니다. 읽음 상태의 일반 메일로 가져오며, EML에 없는 Outlook 전용 상태나 범주를 추정하지 않습니다.
- 인라인 이미지의 Content-ID와 첨부된 EML을 보존합니다. S/MIME 복호화와 TNEF(`winmail.dat`) 내부 파일 추출은 하지 않으며 해당 내용을 첨부로 보존합니다. 원본 EML 첨부가 가장 완전한 원문 보존 수단입니다.
- HTML/텍스트 양식이 모두 있으면 Outlook 항목에는 HTML을 사용합니다. 원래 MIME 구조 및 기타 원본 헤더 전체는 원본 EML 첨부에 남습니다.
- 중지를 누르면 현재 메일을 마친 뒤 멈춥니다. 이미 저장한 항목은 PST에 남습니다. 다시 시작할 때에는 새 PST 이름을 선택하세요. 자동 재개와 중복 제거는 제공하지 않습니다.
- 파일별 오류는 계속 처리하며, PST 옆 `*.conversion.csv`에 성공/실패 및 오류 이유를 남깁니다. 메일 본문은 보고서에 기록하지 않습니다. 성공 0건인 결과를 정상 변환으로 간주하지 마세요.
- PST는 Unicode 형식입니다. Outlook의 PST 용량 제한은 그대로 적용되며 자동 분할은 하지 않습니다. 큰 작업은 원본 폴더를 나누어 처리하세요.
- Outlook 프로세스를 종료하거나 기존 사서함을 변경하지 않습니다. 결과 PST가 연결된 채로 남았다는 안내가 나오면 Outlook에서 해당 데이터 파일을 닫은 후 옮기세요.
- 실행 파일은 코드 서명되지 않았습니다. 조직의 실행 정책이 서명된 앱만 허용하면 해당 정책을 따라야 합니다.

## 검증 상태

Linux 빌드 환경에서 Windows 앱 컴파일과 자체 포함 실행 파일 생성을 검증했습니다. MIME 처리 자동 검사 12개가 통과했습니다(한글·본문·수신자·날짜·첨부 바이너리·인라인 이미지·중첩 메일·안전한 파일명·입력 검증·폴더 구조).

**실제 Outlook COM을 통한 PST 생성과 GUI 실행은 이 Linux 환경에서 실행할 수 없어 검증하지 않았습니다.** 첫 사용은 소수의 EML로 진행해 결과의 본문, 날짜, 보낸 사람 및 첨부를 확인하세요. Outlook 버전이나 보안 정책에 따른 속성 쓰기 오류는 파일별 보고서에서 확인할 수 있습니다.

Windows에서 동작 검증을 하려면 배포 폴더에서 Windows PowerShell을 열고 다음을 실행합니다. 정책상 허용되는 스크립트만 실행하세요.

```powershell
powershell.exe -NoProfile -STA -File .\Outlook-Smoke.ps1 -Executable .\EmlToPst.exe
```

이 스크립트는 임시 폴더에 테스트 EML 두 개를 만들고 실제 PST 생성·다시 열기·한글·날짜·수신자·첨부 바이트·원본 EML·하위 폴더·기존 PST 보호를 검사합니다. Outlook을 종료하지 않으며, 검사 후 임시 폴더 경로를 표시하고 결과를 남깁니다.

## 개발 및 빌드

빌드할 개발자에게만 .NET SDK 10.0.402(또는 같은 기능 밴드의 최신 패치)가 필요합니다. 사용자는 SDK를 설치하지 않습니다.

```powershell
dotnet run --project tests/EmlToPst.Checks --configuration Release
.\scripts\publish.ps1
```

출력은 `artifacts/win-x64/EmlToPst.exe`입니다. NuGet 패키지 버전은 `packages.lock.json`에 고정합니다. 배포할 때 `third-party/`의 라이선스와 .NET 런타임 패키지의 라이선스/고지를 함께 포함하세요. Windows 앱은 하나의 STA 작업 스레드에서 Outlook을 자동화하며 변환 중 UI는 응답할 수 있습니다.
